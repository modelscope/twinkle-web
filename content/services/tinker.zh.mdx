[Tinker](https://tinker-docs.thinkingmachines.ai/) 提供云端训练 API：用户在本地写训练循环，服务端持有模型和 GPU。数据、算法和更新顺序由用户控制，不需要在本机加载基础权重。托管 Tinker 服务与自行部署的 twinkle-server 是不同服务，账号、模型容量和 checkpoint 不能混用。

## 训练契约

```text
ServiceClient → LoRA training client → Datum batches
    → forward_backward → optim_step → save_state
    → sampling client → sample
```

客户端先把数据编码为 token 与 loss 输入，发送 forward/backward 请求，再提交 optimizer 更新。异步 API 返回 future，调用 `result()` 获取执行结果。保存训练状态与保存采样权重是不同操作：恢复训练需要 optimizer 状态和训练进度，采样只需要模型权重。

使用托管 Tinker 前，在官方平台完成服务访问与 API key 配置，并确认模型、价格和额度。安装入口见[官方文档](https://tinker-docs.thinkingmachines.ai/)：

```bash
pip install tinker tinker-cookbook
```

不要用 twinkle 的认证补丁连接托管 Tinker，也不要将 ModelScope token 当作 Tinker 账号凭据。

## 用 Tinker SDK 连接 twinkle-server

已有 Tinker 训练代码可使用 twinkle 的兼容接口，先部署[服务端](/zh/docs/5.0.0.dev/interfaces/server-client)，再安装客户端：

```bash
pip install 'twinkle-kit[client]'
```

保存并运行以下能力查询脚本。`TWINKLE_SERVER_TOKEN` 来自实际服务端；本地未启用认证的示例可不设置：

```python
import os
from twinkle_client import init_tinker_client


init_tinker_client()
from tinker import ServiceClient

service = ServiceClient(
    base_url=os.environ.get('TWINKLE_SERVER_URL', 'http://127.0.0.1:8000'),
    api_key=os.environ.get('TWINKLE_SERVER_TOKEN', ''),
)
for item in service.get_server_capabilities().supported_models:
    print(item.model_name)
```

初始化需在导入 `ServiceClient` 之前执行，用于 twinkle 认证头与 `twinkle://` 路径适配。它不会启动服务、分配 GPU 或自动部署模型。

## 训练与采样

确认模型已部署后，使用 `create_lora_training_client(base_model='Qwen/Qwen3.5-4B', rank=8)` 创建训练句柄，传入已编码的 `Datum`，调用 `forward_backward(data, 'cross_entropy')` 与 `optim_step(AdamParams(...))`。完整数据编码、循环和保存脚本见 [cookbook/client/tinker/self_cognition.py](https://github.com/modelscope/twinkle/blob/main/cookbook/client/tinker/self_cognition.py)。

在完成当前梯度累积、optimizer update 和梯度清除后保存训练状态。`save_state(name).result().path` 返回服务端 checkpoint URI。采样还需部署 sampler application，使用保存的权重构造 sampling client。完整例子见 [sample.py](https://github.com/modelscope/twinkle/blob/main/cookbook/client/tinker/sample.py)。

## 兼容范围

兼容接口目前接受 `cross_entropy` 和 `importance_sampling`。`ppo`、`cispo`、`dro` 不受支持，会在入队和修改梯度之前返回 HTTP 400，不会静默改成 SFT。

twinkle 的 `importance_sampling` 沿用 GRPO loss：默认 `epsilon=0.2` 裁剪、可选 KL（默认 `beta=0`）和按序列取均值。它不同于 Tinker 的不裁剪、token 求和 IS 目标，不能作为数值等价替代。DPO 扩展也使用该入口，但每条 Datum 必须携带 `ref_logps`，chosen / rejected 交错，且每个 DP shard 收到完整 pair。

迁移已有循环时核对 loss 定义、归一化、token mask、批次分发和 checkpoint 路径，不只替换 base URL。完整兼容说明见 [Tinker-Compatible-Client](https://github.com/modelscope/twinkle/blob/main/docs/source_en/Usage%20Guide/Server%20and%20Client/Tinker-Compatible-Client.md)。

## 资源与费用

模型句柄、LoRA rank、同时驻留 adapter 和请求 token 数受服务配置约束。请求成功不表示没有排队或计费；托管费用遵循平台规则，自建成本由部署者承担。只在授权预算内启动训练，并保存实际请求、用量和 checkpoint 记录。ModelScope 托管接入见[ModelScope](./modelscope.mdx)。
