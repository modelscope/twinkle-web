AutoResearch 评测的是“在给定目标与预算下完成研究并改善模型”的过程，不只是单次训练速度。研究 agent 分析目标、选择数据和方法、启动任务、读取指标并调整实验；最终用隔离评测集验证结果。

本期尚无 AutoResearch 实测榜单，因此不展示模型分数或排名。v4 / v5 / remote 的训练曲线与耗时是另一项回归，见[性能报告](/zh/performance)，不能代替自动研究质量。

## 评测流程

```text
固定研究任务与预算 → agent 设计实验 → 训练 / 验证 → 调整实验
                                                     ↓
                               冻结最终 checkpoint → 隔离评测 → 收录
```

每个研究任务在开始前确定基线模型、目标能力、数据许可、训练集、可见验证集、最终隔离评测集和停止条件。参考研究流程见 [AutoResearch skill](https://github.com/modelscope/twinkle/blob/main/src/twinkle_client/skills/bundled/autoresearch.md)；它是流程说明，不是已经完成的榜单结果。

## 评测集与防泄漏

| 能力 | 可用评测类型 | 必须固定的内容 |
|---|---|---|
| 数学推理 | GSM8K、MATH 或任务专用题集 | 数据集 revision、split、判分器、答案提取与采样次数 |
| 代码生成 | HumanEval 或任务专用测试 | 测试版本、隔离执行环境、超时和 pass@k 定义 |
| 通用与领域任务 | 固定分类、问答或指令集合 | rubric、judge 版本或精确匹配规则 |
| 工具与 agent 任务 | 可执行环境中的任务集 | 环境镜像、工具权限、成功条件和最大轮数 |

这些是评测集选择规则，不表示本期已经在这些数据集上得到结果。最终测试集不向研究 agent 提供答案或逐题反馈；训练数据去重与污染检查应覆盖评测 prompt。公开数据的既有预训练污染也需要在报告中说明。

## 预算与控制变量

发布结果必须记录实际预算：GPU 型号与数量、总 GPU 时间、墙钟上限、API token 或费用、最大实验次数、数据生成开销和最终评测开销。失败任务和提前终止任务计入总预算，不只统计最佳运行。

固定 agent 模型及版本、system、技能 ref、工具权限、起始模型 revision、seed 和采样参数。对比方法使用相同允许资源与数据访问；人工干预单独记载，不能与完全自动运行混排。付费服务、长时训练和写入外部资源须获得相应授权。

预算数值与具体任务清单随首批结果发布，目前不设一个没有实际运行依据的统一预算。

## 指标

- **主要结果**：最终隔离集分数及相对基线的变化，报告重复运行数与波动。
- **研究效率**：达到目标的时间、总成本、实验次数和有效实验比例。
- **可靠性**：任务完成率、失败类型、预算超限和人工介入次数。
- **可复现性**：最终代码 / 配置、checkpoint、完整任务记录和环境版本是否齐全。

训练 loss、reward 和 WebUI 的曲线是研究反馈，不自动等于最终评测分数。pass@k、accuracy、judge 分数采用各自定义，不合并成无解释的总分。

## 收录规则

结果提交应包含研究任务书、评测集与版本、预算记录、基线和最终 checkpoint、全程日志、配置与随机种子。只有完成隔离评测、预算可核查且来源完整的结果进入榜单；缺失结果显示未公布，不填零，不推测名次。

不同资源、人工参与或数据权限的结果分组展示。结果更新保留旧版本与更改原因，失败结果与成功结果一并记录。创建研究会话与查看任务的方法见[功能介绍](./features.mdx)。
